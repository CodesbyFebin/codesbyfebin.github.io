Scope of this walkthrough

This note is adapted from a tutorial draft without a reproducible benchmark record. Code blocks are sketches, not a complete crate compiled by this site.

rust-stark-zkvm is a small STARK machine: arithmetic, forward branches, a fixed register file, Winterfell proving, and HTTP/MCP interfaces. The documented verifier re-executes public programs. Private witnesses, a general memory argument, and recursion are outside that documented scope. Do not read this page as a second, larger machine.

Trace, constraints, commitment

A STARK-shaped system still answers three questions. What happened is an execution trace: one row per cycle, one column per piece of state. Was it legal is a set of constraints, polynomials that are zero on an honest trace. Can a verifier check without reading the whole table is a commitment, usually a Merkle root reduced by FRI.

Hold that triad. Later terms such as query count or grinding are adjustments to the commitment and the soundness error. They are not a reason to skip naming the program, the inputs, and the claimed output.

A small teaching ISA

A teaching ISA can stay small on purpose. Each instruction widens the trace or raises constraint degree. The draft used eight operations — add, sub, mul, conditional jumps, load, store, and halt — over 16 registers with R0 hardwired to zero. That is a teaching shape. It is not the instruction list proven by the current rust-stark-zkvm card.

pub enum Op { Add, Sub, Mul, Jz, Jnz, Load, Store, Halt }

The useful security decision in that sketch is the program identity. A proof is about a specific program. If the verifier only checks that some AIR of the right shape accepted a proof, a different program can be substituted. Pin the program hash at the application boundary. The published zkVM card still says to read the AIR and the proof object in the repository before assuming that pin exists.

Execution and determinism

An executor is a fold: fetch, decode, write the next row. Determinism is the requirement. The prover and any re-execution must agree bit for bit, so wall clocks and hash-map iteration order do not belong in the semantics. The draft’s executor used a HashMap for memory. That is a bad place for iteration order to leak into a trace. If you build memory, give it an explicit order.

An AIR constraint for addition, written as a sentence, is: on an add cycle, the next destination register equals the current destination plus the source; on other cycles the add flag is zero and that constraint is idle. Boundary constraints can pin the first program counter and the final halt flag. Degree matters because higher-degree constraints cost more in the proof, but flattening a constraint with a helper column can also make it unsound. Write the obvious constraint first. This note has no timing table for that tradeoff.

Benchmark traps

The tutorial draft supplied benchmark figures without a source revision, exact parameters, or a measurement record. Those figures are not published here.

Three traps are still worth keeping, without the fake table. Nondeterminism: a timestamp or an unordered map in the semantics makes the prover and the verifier disagree. Padding: traces are often padded to a power of two, so a short program still pays for the next power. Benchmark theater: a proof size without hardware, field, security bits, and thread count is an advertisement. A fourth trap is trace bloat: unnecessary columns increase the data processed by the prover.

Security parameters

“96-bit security” is not a mood. It is a claim about the field, the number of FRI queries, and any grinding bits, taken together. A proof envelope that does not carry those parameters cannot be compared with another envelope. This page does not assert a security level for rust-stark-zkvm.

Negative control, matching the repository’s own review note: change the claimed result or the program and confirm rejection. A single accepted proof does not show that the verifier rejects anything else. Recursion cost below 2^16 rows, memory channels, and CI proof gates are not established by this note.
