NixOS: reproducibility as operations

Debian: boring as a feature

Debian's advantages are social and logistical: the largest body of home-server tutorials on earth, live-ISO rescue paths every helper recognizes, LTS support windows that outlive hobby enthusiasm, and package availability without derivation detours. For households where the operator might be unavailable (the succession clause from the exit guide), Debian's universality is a resilience property: the neighbor who "knows Linux" knows Debian. Its drift risk -- the /etc edit made at midnight, the package installed ad hoc -- is real but manageable with the same config-repo discipline (Ansible or plain dotfiles plus apt lists in Git), at the cost of enforcing that discipline yourself rather than inheriting it.

Measured differences that matter at home scale

  • Rebuild time: NixOS full rebuild 3-12 min (evaluation plus build, cached thereafter); Debian reprovision from scratch 20-40 min plus your memory of what was installed.
  • Rollback: NixOS generations instant; Debian snapshots possible via filesystem but package-state rollback remains manual archaeology.
  • Upgrade events: NixOS channel/flake bumps are per-change and revertible; Debian release upgrades are biennial projects with read-the-release-notes rituals.
  • Rescue: Debian live ISO plus muscle memory versus NixOS ISO plus config-aware reinstall -- both fine; the difference is who can wield them besides you.

The verdict I give clients, with the hybrid note

Is the NixOS learning curve worth it for one box?

For one box, marginal: the payoff compounds per additional machine and per additional year, since the config repo becomes a library of proven modules. Single-box households should weigh honestly whether they want a second hobby (Nix) inside the first (self-hosting); both are fine hobbies, but name the choice rather than sliding into it via a forum thread at midnight.

Do Debian containers on a NixOS host combine well?

Excellent pairing: host reproducibility plus guest tutorial-compatibility, with the container image versioned beside the host config. The one discipline: never let guest packages satisfy host needs (a Debian cron inside a container doing host backup is a topology lie); keep layers honest and the hybrid's benefits stay additive instead of confusing.

How do secrets work cleanly on NixOS?

sops-nix or agenix: encrypted files in the same repo, decrypted at build/activation with host keys that never leave the machine -- config public, secrets ciphertext, escrow holding the age keys per the household governance pattern. The arrangement makes "public dotfiles" genuinely safe to publish, which changes what you can share with the community, and sharing is how the contribution ledger grew in the first place.
