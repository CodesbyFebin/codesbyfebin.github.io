The timer: boring, persistent, jittered

The service unit pairs nice and IO scheduling (Nice=10, IOSchedulingClass=best-effort, IOSchedulingPriority=7) with the bandwidth cap in the restic command itself (--bwlimit 20000 KiB/s, raised off-hours via an EnvironmentFile if your nights are emptier than your days). One unit, one journal stream, one place for on-call to look; wrappers that scatter logic across cron lines and shell history are how backups acquire undocumented branches that fail silently the one night they matter.

Retention: deletion with documented intent

The sentences matter operationally: when someone proposes "keep fewer monthlies to save bytes", the conversation becomes about audit windows rather than vibes, and when a restore request arrives for "the state before March's migration", the yearly tier's existence is a decision already made calmly. Prune runs inside the same unit as backup so retention cannot drift from creation, and --prune repacks concurrently with your bandwidth cap -- uncapped prunes on shared targets are the 3 a.m. network incident nobody scheduled.

Keys, locks, and the paranoia that pays

Repository keys live in your secrets manager and the escrow envelope from the exit guide, never on the backed-up host alone. Where the target supports immutability (B2 object lock, append-only storage-box keys), enable it: ransomware that steals credentials still cannot delete history inside the lock window, converting the worst day into a restore-from-before exercise. Rotate repository passwords annually via restic key add then remove, tested like any drill; and keep one air-gapped or friend-hosted copy on rotation with logged swaps, because two targets under one vendor's jurisdiction is one target wearing a costume, a lesson the offsite Q&A prices in vendor-failure rows.

Is restic dedupe enough to skip compression?

Dedupe kills redundancy across snapshots; compression (--compression max) kills redundancy within files -- text-heavy estates (code, logs, dumps) shrink 2-3x with it, encrypted media not at all. Enable max for document/code repos, auto elsewhere, and measure: the size chart per repository tells you in one week whether compression earned its CPU, which is the only argument either side should bring.
