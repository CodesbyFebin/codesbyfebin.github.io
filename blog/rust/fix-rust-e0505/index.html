How Do I Fix Rust Error E0505 Without Cloning Everything?

How to fix Rust error E0505 (value moved while borrowed) without cloning everything: reorderings, scopes, Cow, and the ownership redraw that ends the fight.

Read the error like a map, not a verdict

The three fixes, and when each is right

  • Reorder. Cheapest and most common: move all reads of the borrowed data above the move. Right when the borrow exists only to compute a value you could compute earlier.
  • Narrow scopes. Wrap the borrow in a block so its NLL lifetime ends before the move; or extract the field you need (let name = config.name.clone() or std::mem::take) so the borrow never spans the whole struct. Right when the struct is large but you touch one field.
  • Change ownership. Clone deliberately, use Cow for read-mostly data, or redesign so the consumer owns its input (take Config by value downstream). Right when the borrow genuinely must outlive the move -- then the move is the lie, not the borrow.

When cloning is the wrong answer

Cloning a 40 MB cache to silence E0505 converts a compile-time design signal into a runtime cost and a maintenance trap: the two copies now drift. Signals you are clone-hiding a design problem: clones appearing in hot loops, clones of structs that contain mutexes or handles (partial semantics!), and E0505 returning in a new form after each "fix". At that point redraw instead: message passing (one owner, others ask), an arena with handles (borrow through one door, mutate through another, as in the guide's session example), or Rc/Arc when shared ownership is the truth -- see the cluster Q&A on Rc vs Arc costs for the measured trade-offs before reaching for atomics.
