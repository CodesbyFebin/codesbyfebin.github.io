Three.js scene lifecycle in a React application

Manage rendering, sizing, resources, and teardown when embedding a Three.js scene inside a component-based application.

Use one dependency strategy

The supplied reference describes a component-based application with package imports. Do not mix an old CDN release, a different installed release, and examples from an unrelated API version. Record the dependency version and check its official documentation before choosing loaders, renderer options, or material APIs.

Treat the scene as an owned resource

A scene integration creates resources such as a canvas, renderer, animation loop, geometries, materials, and textures. Give them a lifecycle owner. React component teardown should stop the loop and detach listeners. Removing a DOM element does not automatically dispose every graphics resource.

Size for the actual container

Use the container's available dimensions when updating the renderer and camera aspect ratio. A full-window assumption fails inside a dashboard panel or responsive card. High device-pixel ratios can increase rendering demand; choose a deliberate budget and compare visual quality with observed performance.

Handle load and failure states

A model or texture request can fail or take longer than expected. Show a useful loading state and a readable fallback. Avoid rendering an empty black panel that suggests the entire interface is broken. The surrounding controls should remain usable while assets load.

Respect the product's interaction model

A decorative scene should not intercept scrolling or keyboard input needed by the page. An interactive scene needs visible controls and an explanation of what the user can do. Provide a static or textual path for content that must remain accessible without a working graphics context.

Verify teardown and remounting

Mount and unmount the scene repeatedly, resize its container, and simulate an asset failure. Inspect whether animation continues after teardown or listeners accumulate. The supplied documentation includes an official Three.js reference pack; this article summarizes integration boundaries without claiming that its examples were rendered or benchmarked.
