Which Local Models Are Actually Good for Coding?

Which local models are actually good for coding: benchmark snapshots by size and quantization, tool-call reliability, and the pairs that fit 8 and 16 GB boxes.

The three tiers, with honest job descriptions

  • Completion tier (7-8B coder, Q8): line and block completion, test boilerplate, regex-and-CSV chores. Fast on CPU-plus-small-GPU boxes; errors are local and obvious; the tier where local models beat cloud latency for keystroke-coupled work.
  • Conversation tier (13-14B, Q4-Q6): explain this module, draft this function, convert this pattern; long-context reads of single files plus neighbors. Quality holds when context stays under ~8k of relevant code -- retrieval discipline matters more than model size here, per the RAG guide's chunking rules applied to repositories.
  • Architecture tier (30B+, Q4 where memory allows): cross-module refactoring proposals, migration planning, review commentary. Useful as a senior-ish second reader whose suggestions compile-check before belief; never as an authority, per the verification habits below.

The four-test audition before adoption

  1. FIM discipline: give prefix and suffix of a real function; a coding-capable model respects the suffix boundary instead of rewriting past it.
  2. Diff format: request changes as unified diff on a 300-line file; count malformed hunks across ten runs -- patch-parseable output is the gate for editor integration.
  3. Long-context honesty: embed the question's answer deep in an 8k-token file with two decoys; models that cite the decoy confidently fail, regardless of benchmark fame.
  4. Tool-call restraint: in an agent harness, does the model call search/read tools when context lacks the answer, or hallucinate from priors? Restraint under uncertainty is the trait that predicts safe agent behavior, and it is measurable in an evening.

Workflow integration that survives contact

Editor completion from tier one with a 200 ms debounce and local-only routing (the sensitive-mode toggle from the paste-safety guide); chat and review from tier two behind the gateway with citations-to-file-paths enforced in the prompt; architecture drafts from tier three exported as markdown for human editing, never piped into apply-patch tooling. Compile-and-test feedback loops close the quality gap materially: models whose patches run your test suite improve in effective correctness far beyond their raw benchmark delta, because the suite is a verifier the model cannot charm -- the proof cluster's philosophy arriving in software engineering clothes, verification over vibes.
