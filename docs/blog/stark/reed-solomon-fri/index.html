Low-degree as error-correcting structure

Evaluate a degree-d polynomial on n > d points and you have an RS codeword with distance n - d: any two distinct polynomials differ on most positions. That single fact is the engine of proximity testing: if a committed table is close to some low-degree polynomial, random samples agree with it almost everywhere; if it is far from all such polynomials, no candidate can agree with it on many samples, so sampling catches distance with probability proportional to the distance. Constraints already reduced correctness to "this table is low-degree"; RS distance reduces "is low-degree" to "passes sampling". Two reductions, one amplification -- the reason a verifier touching dozens of positions can speak for millions.

Beyond FRI: where RS shows up elsewhere in the stack

Why not just check random constraints directly without FRI?

Direct sampling of constraint values checks the composition polynomial at points, but nothing ties those points to a committed trace the prover cannot adapt per query; FRI's commitments plus proximity close that loop. Sampling without commitment structure is asking the witness to grade itself -- the gap between an audit and a self-report, which is the gap this entire cluster exists to make technical.

Does RS structure limit which fields I can use?

It requires domains of smooth size (roots of unity) for efficient evaluation and folding, which is why STARK fields are chosen with two-adic structure -- the Goldilocks family's popularity is partly an FFT story. Field selection therefore couples arithmetic speed, security bits, and RS availability; the manifest records the outcome of that coupling, and the field Q&A remains the operational reference for changing it safely.

How does list-decoding relevance show up practically?

Beyond unique-decoding radius, proximity tests enter list-decoding territory where several close polynomials exist; soundness analyses account for this via careful error bounds per fold, which is why published parameter solvers look conservative versus back-of-envelope unique-distance math. Practically: trust the solver, publish its derivation, and treat hand-tuned "improvements" to query counts as soundness changes -- because that is exactly what they are.
