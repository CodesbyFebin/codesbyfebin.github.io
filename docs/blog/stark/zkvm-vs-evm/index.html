Execution models, side by side

DimensionEVMzkVM
Correctness sourceevery validator re-executesone proof, verified by anyone
Cost unitgas per opcode, paid per validationprover cycles, paid once
Statepublic global trieprivate witness + public outputs
Throughput ceilingslowest validator's re-executionprover hardware, parallelizable
Privacynone by defaultwitness hidden by zero-knowledge
Failure modeconsensus split on nondeterminismunsound constraints (testable in CI)

The throughput row is the economic core: EVM transactions pay verification cost on every node forever, while zkVM proofs pay proving cost once and verification cost per interested party, in milliseconds. That inversion is why rollups batch thousands of transactions into one proof -- the chain verifies the receipt, not the work -- and why "zkVM versus EVM" is usually a category error: the interesting systems run EVM-shaped logic inside zkVMs to compress it, the composition pattern the proof-system comparison prices across verifier environments.

Which is cheaper for a one-off internal computation?

Usually plain execution with signed logs: one consumer, no trust boundary, no proof amortization. Add proofs when a second party must check without rerunning -- auditors, partners, future-you with deleted raw data.
