The no_std core: what disappears and what replaces it

Stripping std removes heap allocation, threads, filesystem, and the default panic unwinding -- leaving core plus whatever you bring. The replacements are small and explicit: a panic handler that writes a code to a UART or watchdog register then loops; a linker script placing sections in your flash/RAM map; an entry point (#[no_main] via a PAC/HAL crate or cortex-m-rt) that sets up clocks and jumps to your logic. Everything you loved about Rust survives: traits, iterators over slices, Result-propagated error handling with zero-cost enums. What changes is temperament: every capability is a dependency you chose, which is exactly the sovereignty property this entire portfolio optimizes for, scaled down to 256 KB of flash.

Interrupts and DMA: concurrency with the volume turned down

Embedded concurrency is small and brutal: ISRs sharing buffers with main-loop code, DMA writing memory the compiler believes stable. Rust's answers map cleanly: share via Mutex<RefCell> in cortex-m critical sections or atomics for counters; mark DMA buffers volatile or use dma-safe abstractions (the as-slice/buffer-ownership crates) so the compiler cannot hoist reads above hardware writes; and keep ISRs doing three things -- acknowledge, copy, flag -- with processing deferred to the loop where panics are survivable and tests exist. The type-level trick that pays forever: represent buffer ownership states as types (Empty/Filled/Transferring) so "read a buffer mid-DMA" is a compile error, the make-invalid-states-unrepresentable habit from the systems guide finding its natural home where oscilloscopes charge by the hour.

Probe workflow and the testing pyramid that fits in flash

Development velocity on embedded Rust rests on three tools: a probe (probe-rs or OpenOCD) for flashing and RTT logging without UART wiring rituals, defmt for binary log frames that cost microseconds instead of sprintf milliseconds, and host-side testing of every pure module -- protocol parsers, state machines, math -- which is most of your logic and runs in milliseconds without hardware. The pyramid inverts versus desktop Rust: host tests at the base, probe-in-loop integration in the middle, and field trials at the top measuring the things benches cannot (thermals, brown-outs, radio duty cycles). Teams that skip the host-test base discover their probe budget spent debugging parsers, which is like renting an oscilloscope to proofread a document.

Ecosystem map and first project shape

Start on a well-supported board (STM32 Nucleo, RP2040, nRF) where HAL and PAC crates absorb register-level pain; graduate to reading SVDs when a peripheral lacks coverage, which is your first real embedded-rust rite of passage. First project shape that teaches everything above: a sensor node logging over UART with a panic code protocol, one DMA transfer, one pool allocator, and a host-tested parser for its wire format -- two weekends, every discipline exercised, and a device on your desk that reports its own heap high-water like a good citizen. From there the path branches toward async embedded (embedded-hal-async, Embassy) or bare-metal minimalism; both branches keep the property that made you come: on hardware, the compiler is the only reviewer who never sleeps, never tires, and charges nothing per question -- the systems guide's thesis, at the scale where it matters most.
