A server-side LLM client with explicit cost and failure boundaries

Keep model credentials on the server, validate requests, bound generation, and preserve unavailable and partial-response states.

Keep credentials behind the server boundary

The supplied platform documentation describes a server-injected model API credential. Read it only in server code and never expose it through a client-prefixed variable, response body, or log. A browser calling your server does not need to know the provider credential.

Validate before spending

A model request can consume the owner's quota. Validate the intended operation, input size, and permission before making the provider call. Public endpoints need a usage policy appropriate to the application. A polished button should not hide an unbounded generation loop or automatic repeat calls.

Choose versions from current documentation

Provider model names, endpoints, and supported features change. The supplied platform snapshot is an integration reference, not a live model catalog. Verify the selected model and request shape against the provider's current official documentation. Record the configuration used for any later measurement.

Treat missing configuration as a real state

When the credential is absent or the backend is unavailable, surface an unavailable state. Do not return a fabricated model answer to keep the interface looking complete. Distinguish configuration failure, request validation failure, timeout, and provider rejection so operators can act on the actual problem.

Streaming needs completion semantics

A stream can contain useful partial output and still fail before the operation finishes. Track completion separately from text arrival. Handle cancellation and client disconnects, and decide what generated artifacts survive. If a response triggers a tool action, validate that action through a separate authorization boundary.

Test the inexpensive paths first

Test missing configuration and invalid input without a provider call. Use an explicit budget for a valid integration check, record the selected model, and preserve the observed response status. This static portfolio makes no model API calls; the guide describes the server-side boundary from the supplied integration documentation.
